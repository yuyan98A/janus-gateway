* **[Google PA 工具入参净化与 Claude Code CLI 严格校验双向自愈（2026-10-17）]**：
  1. **EnterPlanMode 意外入参 `reason` 根因定位与合成占位剥除**：
     - **根因剖析**：Google PA Protobuf 要求所有 `OBJECT` 类型参数的 `properties` 字段非空，网关 `schema-sanitizer.ts` 针对空对象 schema 注入了合成占位属性 `reason: { type: 'STRING' }` 并标记为 required；Gemini 模型据此在生成 `EnterPlanMode` 调用时传入了 `{ reason: "..." }`；但 Claude Code CLI 客户端对 `EnterPlanMode` 设定了刚性校验（`additionalProperties: false` 且不接收任何参数），直接抛出 `InputValidationError: EnterPlanMode failed due to the following issue: An unexpected parameter reason was provided`；
     - **治理方案**：实现专用工具入参自愈器 [`healGoogleToolCall`](../../src/providers/google/tool-healer.ts)，在向客户端出站投影工具调用前，针对原工具定义无入参属性的空模式工具（如 `EnterPlanMode`、`TaskList`、`CronList`）强制将入参重置为规范的 `{}`；对于原 schema 中未声明 `reason` 的工具，自动剥除上游合成注入的 `reason` 占位字段；
  2. **Glob 缺失必需参数 `pattern` 根因定位与全链路参数自愈**：
     - **根因剖析**：`schema-sanitizer.ts` 第 4 阶段的属性清洗中，误将校验关键字黑名单 `unsupportedSet`（包含 JSON Schema 正则关键字 `pattern`）应用于对象属性键名（`key`），导致 `Glob` 与 `Grep` 的 `pattern` 参数被当场抹除并从 `required` 数组剔除；Gemini 收到的 `Glob` 声明中仅有 `path` 参数，因此在探索目录时自然生成了 `{ path: "public" }` 而缺失 `pattern`，下游 Claude Code CLI 校验失败报错；
     - **治理方案**：彻底分离 Schema 元数据关键字（`$defs`, `definitions`, `$schema` 等）与常规业务参数属性名，确保 `pattern`、`title`、`format`、`default` 等合法字段完整保留；同时在出站层 `healGoogleToolCall` 中为 `Glob` 增加强韧自愈：若模型仍只传入 `path` 且包含通配符（如 `src/**/*.tsx`）则自动迁移为 `pattern`，若 `path` 为纯目录（如 `public`）则自动补全 `pattern: "**/*"`，彻底杜绝下游校验中断；
  3. **生态常用工具入参规范化**：针对 `Grep`（`query`/`search` 别名映射为 `pattern`）、`FileRead`/`FileWrite`/`FileEdit`（`path`/`filename` 别名映射为 `file_path`）以及 `Bash`（`cmd`/`script` 别名映射为 `command`）提供双向容错修正；

### 模型动态发现与上游可用性验证（2026-10-08）

Google 模型目录现由各启用账号调用上游 `fetchAvailableModels` 获取，缓存 1 天并可从 Models Hub 手动强制刷新；发现结果合并账号模型并保留上游展示名、配额窗口及 thinking 元数据，过滤内部和非聊天模型。当前账号一次发现到 27 个上游条目，其中 22 个作为聊天候选呈现。模型测试对候选发起真实推理；thinking 模型按发现到的最低 thinking budget 调整探测输出长度，批量检查按顺序执行，避免同时突发请求造成误判。详见[模型发现 API](../api/模型发现API.md)。

本次对 22 个 Google 聊天候选执行实测：20 个在适当输出长度或 thinking budget 下返回文本；`gemini-2.5-pro` 返回上游 429 capacity exhausted，尽管发现元数据显示约 98.8% 剩余比例；`gemini-3.1-pro-high` 返回上游 400 invalid argument。发现配额比例不能单独代表模型当前有推理容量。`gemini-3.8-flash-tiered` 与 `gemini-3.6-flash-medium` 均在使用足够的 thinking budget 后通过。多上游端点均失败时，客户端现在保留首个上游错误用于诊断，而不是被后续端点错误覆盖。动态目录也用于路由识别上游返回的非典型 ID（例如 `gpt-oss-120b-medium`）。
