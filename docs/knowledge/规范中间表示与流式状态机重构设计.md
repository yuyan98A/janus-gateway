# 规范中间表示 (Canonical IR) 与工业级 SSE 状态机重构设计

---

## 1. 背景与重构动因

在本项目原有的协议转换架构中：
* **输入端（Ingress）**：支持 Anthropic Messages (`/v1/messages`) 与 OpenAI Chat (`/v1/chat/completions`)；
* **输出端（Egress）**：支持 Google Antigravity 专线（Google Cloud Code PA 内部信封）与 Codex 算力专线（OpenAI Responses API 内部端点）。

### 历史实现的痛点
1. **$M \times N$ 网状转换代码膨胀**：
   - Anthropic ➔ Google PA（手写 `request-builder.ts`）
   - OpenAI ➔ Google PA（将 OpenAI 拼接为临时 `AnthropicRequest` 结构中转）
   - Anthropic ➔ Codex Responses（手写 `request-adapter.ts`）
   - OpenAI ➔ Codex Responses（手写 `request-adapter.ts`）
   - 流式响应解析端也是两套 Provider 分别手写针对 Anthropic 与 OpenAI 的双向 SSE 适配。每次引入新的参数（如思维链控制、Tool Call、多模态）都需要在 4 处适配器同步修改，维护成本随协议与 Provider 增加呈笛卡尔积增长。
2. **简单文本切分的流式边界风险**：
   - 原先采用 `buffer.split('\n')` 的朴素按行切分，在面对极端网络粘包、多字节 UTF-8 字符（如中文或 Emoji）跨 TCP 分包截断、以及 `\r\n` 与 `\r` 混用换行符时，存在隐式乱码或漏包隐患。

---

## 2. 核心架构演进方案

本项目同时落地了两大重构策略：
1. **方案一：引入规范统一中间表示 (Canonical Agent Message IR)**，将系统由 $M \times N$ 网状转换解耦为 $M + N$ 星型架构；
2. **方案二：流式底层换装工业级 EventSource SSE 状态机解析器**，零外部依赖遵循 W3C 规范实现严密流式解析。

### 架构拓扑演进

```text
【重构前：网状转换 (M × N)】
Anthropic In ──┬─➔ Google PA Builder
OpenAI In    ──┼─➔ Codex Responses Builder
               └─➔ ... (需分别维护 4 组转换与 4 组 SSE 状态机)

【重构后：星型架构 (M + N)】
Downstream Ingress                  Canonical Core                   Upstream Providers
Anthropic Messages  ──┐                                       ┌──➔ Google Cloud Code PA
                      ├──➔  GatewayRequestIR  ────────┤
OpenAI Chat           ──┘                                       └──➔ OpenAI Codex Responses

Anthropic SSE       ◄──┐                                       ┌─── Google PA SSE (Parser)
                      ├──◄  GatewayStreamEventIR  ────┤
OpenAI Chat Chunks  ◄──┘                                       └─── Codex Responses SSE (Parser)
```

## 3. 规范统一中间表示 (IR) 规格

规范定义于 `src/protocol/ir.ts`：

### 3.1 请求中间表示 (`GatewayRequestIR`)
```typescript
export interface GatewayRequestIR {
  model: string;
  systemPrompt?: string;
  messages: UnifiedMessage[];
  tools?: UnifiedTool[];
  toolChoice?: any;
  maxTokens?: number;
  temperature?: number;
  topP?: number;
  topK?: number;
  stream: boolean;
  reasoningEffort?: string;
  thinkingBudget?: number;
  sourceProtocol: 'anthropic' | 'openai';
  rawRequest?: any;
}
```

* `messages` 内标准化为 `UnifiedContentPart[]`：
  - `text`: 普通文本
  - `image`: 多模态图片（支持 Base64 与 URL）
  - `tool_use`: 结构化工具调用（`id`, `name`, `input`）
  - `tool_result`: 结构化工具回填（`toolCallId`, `content`, `isError`）
  - `thinking`: 思维链思考块（`thinking`, `signature`）

### 3.2 流式事件中间表示 (`GatewayStreamEventIR`)
模型生成流在内部统一规整为状态机事件：
- `start`: 携初始会话 ID、模型名称及输入 Token 统计
- `thinking_start` / `thinking_delta` / `thinking_stop`: 思维链流式块
- `text_start` / `text_delta` / `text_stop`: 最终正文流式块
- `tool_call_start` / `tool_call_delta` / `tool_call_stop`: 工具调用与参数增量拼装
- `finish`: 结束标志，附带 `stopReason`（`end_turn` | `tool_use` | `max_tokens`）与 Token 用量
- `error`: 异常事件

## 4. 工业级 EventSource SSE 状态机解析器

实现于 `src/utils/event-source-parser.ts`：
1. **遵循 W3C EventSource 标准规范**：
   - 正确解析 `data:`, `event:`, `id:`, 以及以 `:` 开头的注释忽略行；
   - 支持同一事件内多个 `data:` 行自动以 `\n` 合并；
   - 兼容任意换行符类型（`\r\n`, `\n`, `\r`），精准处理跨包残缺行及末尾单 `\r` 缓冲；
2. **零依赖安全 UTF-8 解码**：
   - 封装 `parseEventSourceStream(ReadableStream<Uint8Array>)`；
   - 内部利用 `TextDecoder('utf-8', { stream: true })` 自动保留跨 chunk 未完成字节，彻底杜绝中文与 Emoji 乱码；
3. **全局 Provider 统一复用**：
   - Codex Responses SSE 解析
   - Google Cloud Code PA SSE 解析
   - Google Reasoning 探针流解析
